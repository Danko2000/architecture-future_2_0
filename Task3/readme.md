# Стратегия технологического развития «Будущее 2.0»

Здесь описывается целевое состояние технологического ландшафта компании через 1 год. 
Включает в себя визуализацию стека технологий (Технический радар), 
план перехода (Роадмап) и бизнес-обоснование изменений.

---

## 1. Технический Радар «Будущее 2.0»

Технический радар классифицирует технологии по степени их зрелости и применимости в компании. Мы используем 4 стандартных квадранта и 4 кольца жизненного цикла:

* **Adopt (Внедрять):** Устоявшиеся технологии для новой архитектуры.
* **Trial (Пробовать):** Технологии для пилотных проектов (например, в Финтехе).
* **Assess (Изучать):** Перспективные технологии для будущих интеграций.
* **Hold (Выводить):** Устаревшие технологии, запрещенные для новых разработок.

### Квадрант 1: Практики и Паттерны (Methods & Patterns)
*Архитектурные подходы и методологии разработки.*

| Технология | Кольцо | Поддерживаемый бизнес-сценарий |
| :--- | :--- | :--- |
| **Data Mesh** | **Adopt** | **Интеграция новых бизнесов.** Позволяет финтеху и медицине развиваться автономно, управляя данными как продуктом. |
| **ELT (Extract-Load-Transform)** | **Adopt** | **Масштабирование (M&A).** Быстрая загрузка данных новых покупок (Фарма) в озеро без предварительной обработки ускоряет Time-to-Market. |
| **Domain-Driven Design (DDD)** | **Adopt** | **Качество сервисов.** Четкое разделение бизнес-логики и границ ответственности между доменами снижает количество ошибок. |
| **Monolithic Architecture** | **Hold** | **Снижение рисков.** Отказ от монолита устраняет единую точку отказа и позволяет проводить релизы чаще. |

### Квадрант 2: Платформы (Platforms)
*Инфраструктура, на которой работает ПО.*

| Технология | Кольцо | Поддерживаемый бизнес-сценарий |
| :--- | :--- | :--- |
| **Cloud Data Lake (S3)** | **Adopt** | **Масштабирование отчетности.** Хранение сотен терабайт данных (снимки, логи) в облаке дешевле и надежнее on-premise решений. |
| **Docker / Kubernetes** | **Adopt** | **Гибкость и надежность.** Автоматическое масштабирование финтех-сервисов под нагрузкой. |
| **SQL Server 2008** | **Hold** | **Безопасность.** Устаревшая платформа, снятая с поддержки. Перевод в режим Read-Only для минимизации рисков. |

### Квадрант 3: Инструменты (Tools)
*Базы данных, брокеры сообщений и системы управления.*

| Технология | Кольцо | Поддерживаемый бизнес-сценарий |
| :--- | :--- | :--- |
| **Apache Airflow** | **Adopt** | **Управляемость процессов.** Оркестрация сложных потоков данных между разнородными системами (Legacy, Финтех, ИИ). |
| **ClickHouse** | **Adopt** | **Скорость принятия решений.** Построение аналитических отчетов за секунды вместо часов (Витрина данных). |
| **BI Portal (Self-Service)** | **Trial** | **Демократизация данных.** Пилотный проект, позволяющий менеджерам самостоятельно строить отчеты без участия IT. |
| **PowerBuilder** | **Hold** | **Снижение затрат.** Постепенный отказ от дорогого в поддержке интерфейса в пользу веб-технологий. |
| **Apache Camel (Legacy)** | **Hold** | **Устранение узких мест.** Замена старой шины на современные потоковые интеграции через Data Lake. |

### Квадрант 4: Языки и Фреймворки (Languages & Frameworks)
*Инструменты для написания кода.*

| Технология | Кольцо | Поддерживаемый бизнес-сценарий |
| :--- | :--- | :--- |
| **Python** | **Adopt** | **ИИ и Инновации.** Основной язык для ML-моделей диагностики и инженерии данных. |
| **Go / Java** | **Trial** | **Финтех-сервисы.** Высокопроизводительные языки для реализации транзакционной логики банка (пилот). |
| **IoT Protocols (MQTT)** | **Assess** | **Новые рынки.** Изучение протоколов для интеграции с производителем электроники (носимые мед. устройства). |

## 2. Технологический Роадмап (Roadmap)

План реализации стратегии на 1 год, разбитый на этапы с привязкой к бизнес-целям.

### Этап 1: Фундамент и Безопасность (Месяцы 1-3)
* **Бизнес-цель:** Обеспечить безопасный запуск финтеха, исключив доступ к врачебной тайне, и снизить нагрузку на Legacy DWH.
* **Шаги:**
    1.  Развертывание **Cloud Data Lake** и настройка контуров безопасности (Медицина vs Финансы).
    2.  Настройка репликации данных из SQL Server 2008 в Озеро (Raw Zone).
* **Ответственные:** Команда Платформы данных, ИБ.
* **Ресурсы:** Облачная подписка, DevOps-инженеры.
* **Результат:** Данные защищены и доступны для аналитики в облаке. SQL Server разгружен.

### Этап 2: Пилот Data Mesh и Независимость (Месяцы 4-6)
* **Бизнес-цель:** Обеспечить независимый запуск финансовых продуктов и ускорить обучение ИИ-моделей.
* **Шаги:**
    1.  Запуск домена «Финтех» на микросервисах (**Go/Java**).
    2.  Подключение ИИ-сервисов (**Python**) напрямую к Озеру данных (минуя DWH).
    3.  Внедрение **Apache Airflow** для управления потоками.
* **Ответственные:** Команды Финтеха и ИИ.
* **Ресурсы:** Разработчики Go/Python, Data Engineers.
* **Результат:** Финтех выпускает релизы автономно. ИИ получает данные без задержек.

### Этап 3: Портал Самообслуживания (Месяцы 7-9)
* **Бизнес-цель:** Сокращение времени получения отчетов (Time-to-Decision) и снижение операционной нагрузки на IT.
* **Шаги:**
    1.  Запуск Витрины Данных на **ClickHouse**.
    2.  Внедрение **BI Portal** и обучение бизнес-пользователей работе с ним.
    3.  Миграция критической отчетности из SQL Server.
* **Ответственные:** Команда Аналитики.
* **Ресурсы:** Лицензии BI, обучающие материалы.
* **Результат:** Аналитики строят отчеты самостоятельно за минуты.

### Этап 4: Масштабирование и Вывод Legacy (Месяцы 10-12)
* **Бизнес-цель:** Техническая готовность к M&A (Фарма, Электроника) и снижение затрат на поддержку устаревшего ПО.
* **Шаги:**
    1.  Разработка API и контрактов данных для внешних партнеров.
    2.  Полный запрет (Hold) на доработки в **PowerBuilder** и **SQL Server**.
    3.  Начало пилота по интеграции IoT-данных (**MQTT**).
* **Ответственные:** Архитекторы.
* **Ресурсы:** Бюджет на интеграцию.
* **Результат:** Компания готова подключить нового партнера за 2 недели.

## 3. Обоснование изменений

Переход по кольцам радара требует наличия проблемы или потребности. Ниже приведено обоснование ключевых движений.

### A. Внедрение Data Mesh и Cloud Data Lake
* **Проблема:** Монолитный DWH стал узким местом. Любое изменение требует длительных согласований, что блокирует развитие новых направлений (Финтех).
* **Бизнес-ценность:** **Скорость вывода продуктов (Time-to-Market).** Разделение на домены позволяет командам работать параллельно. Использование Data Lake позволяет дешево хранить и обрабатывать любые объемы данных от новых активов (Фарма), что критично для масштабирования.

### B. Переход на ClickHouse и Self-Service BI
* **Проблема:** Отчеты строятся часами, руководство получает устаревшие данные. IT-отдел перегружен рутинными запросами на выгрузки.
* **Бизнес-ценность:** **Скорость принятия решений и Снижение затрат.** Руководство видит ситуацию в реальном времени. Менеджеры сами создают отчеты, освобождая дорогих инженеров для решения стратегических задач.

### C. Изоляция Legacy (Hold для SQL Server и PowerBuilder)
* **Проблема:** Технологии сняты с поддержки, специалистов на рынке мало, высок риск сбоев и проблем с безопасностью (например, уязвимости в старых версиях).
* **Бизнес-ценность:** **Качество сервиса и Безопасность.** Мы "замораживаем" старую систему, гарантируя, что новые эксперименты в финтехе не нарушат работу клиники. Плавный вывод из эксплуатации минимизирует операционные риски.
